## 边界与定位说明

本功能（001）定位为**纯粹的底层空间感知与几何数据 API 基建**，其核心职责是“精确解算物理世界的空间几何数据”。

- **本阶段包含范围**：相机连接与视频流拉取、DAP 深度估计、空间三维反投影与重力对齐、纯动态地面分离、人类生理视觉范围障碍物空间场解算、动态接近速率评估、安全通行走廊计算、地面跌落断层检测，以及向外输出标准化的结构化数据。
- **本阶段不包含范围**：具体的非视觉反馈编排（如复杂的 VoiceOver 语音文案播报规则、多段触觉震动马达编排）。上层将作为本 API 的消费者，直接获取本层输出的空间三维坐标与角度数据，驱动 iPhone 的空间音频（Spatial Audio）进行听觉定位。

## 用户场景与独立测试

### 用户场景 1：安全通行走廊几何解算（优先级：P1，核心 MVP）

作为上层交互开发者或视障应用使用者，当处于室内通道或开门场景时，我希望底层 API 能够实时解算出前方是否存在可供通行的空间，并输出建议行进的方位角、通道瓶颈宽度以及安全纵深，以便上层能够将空间音频的引导音精准放置在通道中心方向。

- **优先级理由**：行走导航的第一核心是“找到出路”。解算出真实空间中哪条路径安全可行，是后续空间音频引导的基石。
- **独立测试验证**：在设有 0.9 米宽开放房门和两侧障碍物的测试环境中，API 能够稳定输出通道可用状态，并给出指向门中心的偏转角度与物理净宽。
- **验收场景**：
  1. **场景一（正前方有门）**：当用户正对 2 米外的敞开房门时，API 输出通道状态为可用，建议偏转角为 0 度，通道净宽与真实门框尺寸误差小于 0.05 米，可通行纵深大于 2 米。
  2. **场景二（侧方有门）**：当房门位于用户右前方 20 度方向时，API 输出建议偏转角为正 20 度，并输出门框处的空间三维坐标。
  3. **场景三（通道受阻）**：当房门关闭或前方完全被障碍物封闭时，API 输出通道状态为不可用，引导纵深为 0。

---

### 用户场景 2：生理视角动态障碍物感知与优先级排序（优先级：P1）

作为上层交互开发者，我希望底层 API 能够聚焦于人类生理视觉空间范围（正前方水平约 120° 至 140° 视野），感知前方行进视野内的障碍物，并根据距离远近与动态逼近速度进行动态优先级分级，每帧仅输出威胁最高的 Top 3 个障碍物空间相对坐标（X 水平偏移、Y 垂直高度、Z 前后纵深），以便上层直接驱动最多 3 个 3D 空间音频声源，避免造成盲人听觉混乱。

- **优先级理由**：生理视觉范围聚焦与动态接近加权能够有效滤除身后的无关干扰，将 AirPods 的并发声源严格限制在 3 个以内，符合无障碍认知负荷最优实践。
- **独立测试验证**：在使用者正前方不同距离放置障碍物，并测试静止物体与动态迎面逼近物体的优先级输出顺序。
- **验收场景**：
  1. **场景一（动态逼近物体优先）**：前方 2 米处有一静止桌子，左前方 2.5 米处有行人正向使用者走来。API 识别出行人的动态逼近速度，并将其优先级排在静止桌子之前输出。
  2. **场景二（侧向余光防刮擦）**：在用户左前方 50 度（处于生理视角边缘）1 米处有立柱，API 稳定输出该障碍物坐标，标明其为侧翼威胁。
  3. **场景三（身后无关物体忽略）**：在用户正后方 180 度 1 米处有墙壁，由于超出人类生理视角前向关注范围，API 不将其作为主行进障碍物输出，防止后方声音干扰前向判断。

---

### 用户场景 3：地面跌落断层与下行阶梯几何检测（优先级：P2）

作为上层交互开发者，我希望底层 API 能够持续监视使用者脚下前方的地面连续性，一旦检测到前方地面存在超过 15 厘米的向下断崖式落差，立即输出跌落边缘的方位角、距离和落差值，以便上层能立即播放紧急警示音，防止视障者踩空摔伤。

- **优先级理由**：踩空跌落是视障者出行中致伤率最高的危险场景，是安全底线。
- **独立测试验证**：在距离下行台阶或地面凹坑 1.5 米处移动，API 能够精准捕捉到地面深度突变点，并输出距离边缘的物理距离。
- **验收场景**：
  1. **场景一（下行台阶检测）**：在前方 1.2 米处出现 15 厘米以上向下阶梯时，API 输出跌落警报事件，标明边缘距离为 1.2 米，落差大于 0.15 米。
  2. **场景二（正常平地连续性）**：在普通平整路面上行走时，路面自然纹理不被误判为跌落事件。

---

### 用户场景 4：相机实时流与离线样本双轨注入（优先级：P3）

作为算法和系统开发人员，我希望底层 API 能够透明支持真实 Insta360 全景相机流与离线全景样本序列两种输入模式，且对外暴露统一的数据帧与姿态接口。

- **优先级理由**：解耦硬件连接依赖，使算法研发、测试与上层音频编排可以脱离实体相机并行推进。
- **独立测试验证**：在连接真实相机与读取本地全景图序列两种模式下，API 能够以相同的数据结构向下游输出感知结果。
- **验收场景**：
  1. **场景一（相机实时流接入）**：开启 Insta360 相机 Wi-Fi 后，模块自动建立连接，拉取全景视频流并同步读取陀螺仪姿态。
  2. **场景二（离线数据驱动）**：未连接相机时，模块读取本地全景图像，以每秒 8 帧的速率稳定向推理管道输送数据。

### 边缘情况 (Edge Cases)

- **相机穿戴倾斜与晃动**：用户行走时相机会产生俯仰与翻滚。底层 API 必须利用传感器数据进行重力方向对齐，确保输出的 $(x, y, z)$ 坐标系中，Y 轴严格垂直于重力方向，防止因相机倾斜将地面误判为障碍物。
- **近距噪点与盲区（小于 0.3 米）**：当障碍物过于贴近镜头时，深度可能出现离群噪点。API 需对此类数据进行安全兜底，统一按极近危险输出。
- **平滑低纹理墙面与高反光镜面**：面对无纹理白墙或镜面时，深度估计可能出现瞬时跳变。API 需在空间几何层引入时间平滑滤波，剔除单帧孤立噪点。
- **相机通信闪断**：无线信号受到干扰导致丢帧或断连时，API 必须在 1 秒内对外输出连接状态异常事件，严禁内部静默挂起或输出脏数据。

## 需求规范 (Requirements)

### 功能需求 (Functional Requirements)

- **FR-001**：系统必须支持通过无线网络或有线接口连接 Insta360 全景相机，并持续拉取全景视频流与三轴姿态传感器数据。
- **FR-002**：系统必须提供离线数据源模拟器，支持使用本地全景图像或视频序列注入管道进行算法验证。
- **FR-003**：系统必须能够从全景图像中估计全向物理距离，测距有效范围覆盖 0.3 米至 5.0 米，单点测距误差小于 5 厘米。
- **FR-004**：系统必须利用传感器姿态数据对空间点云进行重力对齐校准，消除相机倾斜对坐标系的影响。
- **FR-005**：系统必须通过对全景下半球深度点云进行实时纯动态平面拟合（如 RANSAC 平面解算），自适应动态计算相机当前离地高度与地平面方程，无需任何人工高度先验或静态标定，并据此剥离脚下平整地面，提取地面上方 0.1 米至 2.0 米之间的障碍物点云。
- **FR-006**：系统必须将主避障检测空间限定在人类生理视觉角度范围内（水平前向正负 60 度至 70 度，总视野约 120 度至 140 度），专注行进方向的安全防护。
- **FR-007**：系统每帧输出的障碍物对象列表必须严格限制为最多 Top 3 个，采用“物理距离越近优先级越高”并叠加“动态相对接近速率（距离缩减率）越快优先级越高”的加权评分模型进行动态排序与截断。
- **FR-008**：每个输出的障碍物对象必须包含三维相对空间坐标 $(x, y, z)$（水平、高度、纵深，单位：米）、方位角（度）、绝对距离（米）以及动态接近速率（米/秒）。
- **FR-009**：系统必须基于人体宽度（默认 0.6 米）计算前方安全通行走廊，输出建议行进方位角（度）、通道瓶颈物理净宽（米）以及安全可行进纵深（米），并给出走廊中心的三维空间导向锚点坐标 $(x, y, z)$。
- **FR-010**：系统必须监测正前方地面高度变化，在前方地面出现超过 15 厘米的向下阶跃落差时，输出跌落隐患事件及其距离和方位。
- **FR-011**：系统必须以标准结构体或内存数据流形式对外暴露上述计算结果，接口三维坐标系必须与 iOS 空间音频（AVAudio3DMixing）保持直接兼容。
- **FR-012**：在相机连接断开或数据源异常时，系统必须在 1 秒内更新数据状态标志为异常，供上层感知。

### 关键数据实体 (Key Entities)

- **全景数据帧 (PanoramicFrame)**：包含全景图像像素缓存、采集时间戳、相机三轴角速度与重力姿态角。
- **物理深度矩阵 (DepthMatrix)**：全向 256 行乘 512 列的物理距离矩阵，记录每个方向的精确测距值（米）及有效性标志。
- **空间障碍物项 (SpatialObstacleItem)**：描述单个障碍物在使用者相对坐标系中的空间位置（每帧最多输出 3 项）：
  - `position`: 三维相对坐标 $(x, y, z)$，单位：米；
  - `distance`: 空间直线距离，单位：米；
  - `azimuth`: 水平偏转方位角，单位：度（负值为左，正值为右，范围限制在前向生理视角内）；
  - `elevation`: 垂直仰角，单位：度（负值为低矮，正值为上方）；
  - `approachRate`: 动态相对接近速率（米/秒，正值表示正在快速逼近）；
  - `priorityScore`: 综合威胁优先级评分；
  - `threatLevel`: 威胁级别（安全、警告、危险）。
- **通行走廊几何 (PassageCorridorGeometry)**：描述当前最佳通行走廊：
  - `isPassable`: 是否存在可通过走廊（布尔值）；
  - `recommendedSteeringAngle`: 建议行进方位角（度）；
  - `clearanceWidth`: 通道最窄处的物理净宽（米）；
  - `passableDepth`: 安全可行进纵深距离（米）；
  - `targetAnchor`: 通道中心的三维空间导向坐标 $(x, y, z)$（供空间音频直接绑定音源）。
- **跌落危险事件 (DropOffHazardEvent)**：描述地面踏空风险：
  - `distance`: 距离使用者的水平距离（米）；
  - `azimuth`: 危险边缘所在方位角（度）；
  - `dropDepth`: 预估向下落差深度（米）。

## 成功指标 (Success Criteria)

### 可度量指标 (Measurable Outcomes)

- **SC-001（端到端低延迟）**：底层全链路处理延迟（从图像输入到输出空间几何数据）控制在 130 毫秒以内，稳定维持每秒 8 帧以上的更新速率。
- **SC-002（物理测距高精度）**：在 0.5 米至 3.0 米的有效避障核心区间内，空间三维坐标与距离的平均测量误差小于 3 厘米（相对误差小于 3%）。
- **SC-003（通道几何识别率）**：在室内典型开门与过道测试中（如 0.9 米标准门宽），安全通行走廊的检出率达到 95% 以上，且建议方位角偏差小于 8 度。
- **SC-004（生理视角内高危障碍物检出率）**：在使用者生理视觉范围（前向 120 度至 140 度）身周 2 米内，对体积大于 20 乘 20 乘 20 厘米的障碍物检出率达到 98% 以上。
- **SC-005（动态逼近加权有效性）**：当存在相对速度大于 0.5 米/秒的迎面逼近物体时，系统在 2 帧（约 250 毫秒）内将其动态提升为 Top 1 最高优先级。
- **SC-006（纯动态地平面自适应性）**：在相机高度在 0.8 米至 1.8 米（手持、胸前、头盔）变化时，地平面拟合误差小于 5 厘米，无需任何手动标定。
- **SC-007（跌落边缘预警时机）**：针对 15 厘米以上的下行阶梯或坑洼，在距离边缘 1.2 米前检出率达到 95% 以上。
- **SC-008（空间音频接口直接可用性）**：上层空间音频引擎无需额外坐标变换，可直接利用本 API 输出的 `targetAnchor` 或 `position` 进行音源位置更新，数据对接耗时小于 1 毫秒。

## 假设与约束 (Assumptions)

- **相机安装自适应**：全景相机支持手持、胸前、肩部或头盔佩戴，系统纯动态解算地平面与相机高度，要求镜头水平 360 度视野无遮挡，镜头正前方与身体朝向基本一致。
- **使用者移动工况**：假设用户处于正常步行速度（约每秒 0.8 至 1.2 米）。
- **下游使用方式**：假设上层业务层专门负责将本 API 输出的三维坐标赋予 iOS 空间音频节点，本模块自身不调用任何音频播放或震动驱动 API。
- **通信与计算资源**：假设在 iPhone 15 及以上搭载 Apple 神经引擎（ANE）的设备上独立脱机运行。
