## 边界与定位说明

本功能（001）定位为**纯粹的底层空间感知与几何数据 API 基建**，其核心职责是“精确解算物理世界的空间几何数据”。

- **本阶段包含范围**：Insta360 真实相机连接与生命周期管理、设备连接/断开与画面/传感器预览 UI、全景实时流拉取与解码、六轴 IMU 传感器解析、DAP 深度估计、空间三维反投影与重力对齐、纯动态地面分离、安全通行走廊计算、人类生理视觉范围障碍物空间场解算、动态接近速率评估、用户运动状态（前行/静止/后退）感知、动态后向倒车雷达切换、前后双向地面跌落断层检测，以及向外输出标准化的结构化数据。
- **本阶段不包含范围**：具体的非视觉反馈编排（如复杂的 VoiceOver 语音文案播报规则、多段触觉震动马达编排）；不包含离线图像模拟回放功能（直接基于真实相机开发测试）。上层将作为本 API 的消费者，直接获取本层输出的空间三维坐标与角度数据，驱动 iPhone 的空间音频（Spatial Audio）进行听觉定位。

## 澄清记录 (Clarifications)

### 会话 2026-09-22
- Q: 多障碍物输出与空间音频声源数量策略？ → A: 采用 Top 3 分级筛选，主检测空间限定为人类生理视觉角度（水平前向约 120°~140°，即正前方 ±60°~±70° 扇区），并根据距离远近及动态接近速率（接近速度越快、距离越近优先级越高）进行动态威胁排序。
- Q: 地平面识别与相机安装高度先验策略？ → A: 采用纯动态地平面拟合（Option A），完全不依赖固定高度先验或人工静态标定，算法对全景下半球深度点云进行实时平面拟合以动态获取相机离地高度与地平面方程，自适应支持手持、胸前、肩部或头盔等任意佩戴姿态。
- Q: 用户姿态与运动意图感知及后退保护策略？ → A: 利用相机 IMU 纵向加速度脉冲与全景前后深度差分轻量解算用户运动状态（前行 forward / 静止 stationary / 后退 backward）。常态下聚焦前向生理视角；一旦检测到后退意图，主检测空间自适应切换为后方 180°（倒车雷达模式），优先输出身后 Top 3 障碍物与后向防踩空跌落风险。
- Q: 是否需要开发离线全景样本回放与模拟器？ → A: 不需要（移除）。团队直接在 Insta360 真实物理相机上进行端到端开发与真机联调，遵循宪章的 YAGNI 原则，砍掉离线模拟器抽象以集中精力攻克真实视频流与传感器管线。
- Q: 需求场景与工程落地的首要优先级次序？ → A: 将“相机连接、生命周期管理与实时流接入”调整为第 1 优先级（P1，核心基石），并为其配备设备连接/断开与画面/传感器预览 UI，直观验证硬件流水线连通性。

## 用户场景与独立测试

### 用户场景 1：Insta360 全景相机连接、控制 UI 与实时流预览（优先级：P1，核心基石 / 阻塞性前提）

作为开发者和系统使用者，我希望在手机上能有一个极简、无障碍友好的控制界面，可以一键连接或断开 Insta360 全景相机，全面管理相机的生命周期；并在连接成功后，能够直接在界面上看到全景实时视频预览画面，以及实时的六轴传感器（IMU）姿态数据面板，以便直观验证相机通信正常、画面流畅、姿态数据同步，为下游管线提供坚实的数据源保障。

- **优先级理由**：没有真实相机的实时画面与传感器数据输入，下游的模型推理、点云投影与空间避障均无法运转。直观的控制与预览 UI 是验证硬件数据链路通畅的最快抓手。
- **独立测试验证**：在 iPhone 上点击“连接设备”，应用与 Insta360 相机在 2 秒内完成握手建连，界面实时渲染 1080P 全景视频流（每秒 15 帧以上），传感器面板持续刷新三轴姿态角与加速度；点击“断开设备”后，安全释放流并断开连接。
- **验收场景**：
  1. **场景一（设备连接与实时画面渲染）**：打开 App，点击“连接设备”按钮（尺寸至少 48x48 像素，配有 VoiceOver 标签），应用成功连上相机 Wi-Fi，界面中央立即流畅播放全景实时预览画面，无黑屏与画面撕裂。
  2. **场景二（传感器实时数据面板）**：界面下方的信息面板实时显示当前连接状态（如“已连接”）、实时帧率（FPS）、三轴姿态角（俯仰/翻滚/偏航）与加速度数值，数据随相机转动连续平滑刷新；遵循无障碍边界阻断原则合并为单一语义卡片，支持 VoiceOver 整体聚焦并以中文逗号平铺朗读，防止焦点碎片化。
  3. **场景三（主动断开连接）**：点击“断开设备”按钮，系统安全关闭流播放器并断开连接，预览画面清空，状态更新为“未连接”。
  4. **场景四（异常断开与自动重连提示）**：若相机电量不足或 Wi-Fi 信号异常中断，界面在 1 秒内更新状态为“连接中断，正在重连”，并通过 VoiceOver 向用户播报断连提示。

### 用户场景 2：安全通行走廊几何解算（优先级：P1，核心导向）

作为上层交互开发者或视障应用使用者，当处于室内通道或开门场景时，我希望底层 API 能够实时解算出前方是否存在可供通行的空间，并输出建议行进的方位角、通道瓶颈宽度以及安全纵深，以便上层能够将空间音频的引导音精准放置在通道中心方向。

- **优先级理由**：行走导航的第一核心是“找到出路”。解算出真实空间中哪条路径安全可行，是后续空间音频引导的基石。
- **独立测试验证**：在设有 0.9 米宽开放房门和两侧障碍物的测试环境中，API 能够稳定输出通道可用状态，并给出指向门中心的偏转角度与物理净宽。
- **验收场景**：
  1. **场景一（正前方有门）**：当用户正对 2 米外的敞开房门时，API 输出通道状态为可用，建议偏转角为 0 度，通道净宽与真实门框尺寸误差小于 0.05 米，可通行纵深大于 2 米。
  2. **场景二（侧方有门）**：当房门位于用户右前方 20 度方向时，API 输出建议偏转角为正 20 度，并输出门框处的空间三维坐标。
  3. **场景三（通道受阻）**：当房门关闭或前方完全被障碍物封闭时，API 输出通道状态为不可用，引导纵深为 0。

### 用户场景 3：生理视角动态障碍物感知与优先级排序（优先级：P1，核心避障）

作为上层交互开发者，我希望底层 API 能够聚焦于人类生理视觉空间范围（正前方水平约 120° 至 140° 视野），感知前方行进视野内的障碍物，并根据距离远近与动态逼近速度进行动态优先级分级，每帧仅输出威胁最高的 Top 3 个障碍物空间相对坐标（X 水平偏移、Y 垂直高度、Z 前后纵深），以便上层直接驱动最多 3 个 3D 空间音频声源，避免造成盲人听觉混乱。

- **优先级理由**：生理视觉范围聚焦与动态接近加权能够有效滤除身后的无关干扰，将 AirPods 的并发声源严格限制在 3 个以内，符合无障碍认知负荷最优实践。
- **独立测试验证**：在使用者正前方不同距离放置障碍物，并测试静止物体与动态迎面逼近物体的优先级输出顺序。
- **验收场景**：
  1. **场景一（动态逼近物体优先）**：前方 2 米处有一静止桌子，左前方 2.5 米处有行人正向使用者走来。API 识别出行人的动态逼近速度，并将其优先级排在静止桌子之前输出。
  2. **场景二（侧向余光防刮擦）**：在用户左前方 50 度（处于生理视角边缘）1 米处有立柱，API 稳定输出该障碍物坐标，标明其为侧翼威胁。
  3. **场景三（身后无关物体忽略）**：在用户正后方 180 度 1 米处有墙壁，由于处于正常前行状态且超出前向生理视角，API 不将其作为主行进障碍物输出，防止后方声音干扰前向判断。

### 用户场景 4：地面跌落断层与下行阶梯几何检测（优先级：P2，安全底线）

作为上层交互开发者，我希望底层 API 能够持续监视使用者脚下前方的地面连续性，一旦检测到前方地面存在超过 15 厘米的向下断崖式落差，立即输出跌落边缘的方位角、距离和落差值，以便上层能立即播放紧急警示音，防止视障者踩空摔伤。

- **优先级理由**：踩空跌落是视障者出行中致伤率最高的危险场景，是安全底线。
- **独立测试验证**：在距离下行台阶或地面凹坑 1.5 米处移动，API 能够精准捕捉到地面深度突变点，并输出距离边缘的物理距离。
- **验收场景**：
  1. **场景一（下行台阶检测）**：在前方 1.2 米处出现 15 厘米以上向下阶梯时，API 输出跌落警报事件，标明边缘距离为 1.2 米，落差大于 0.15 米。
  2. **场景二（正常平地连续性）**：在普通平整路面上行走时，路面自然纹理不被误判为跌落事件。

### 用户场景 5：动态后退意图识别与后向倒车雷达保护（优先级：P2，全景特色）

作为视障使用者与上层开发者，当我因避让或犹豫而起步向后退时，我希望底层 API 能敏锐捕捉到我的后退动作，瞬间将避障重心切换为身后 180 度范围，检测身后是否有障碍物或下行台阶踏空风险，并在身后相对坐标系中输出危险数据，让耳机在脑后发出警示，避免盲人后退发生意外碰撞或踩空。

- **优先级理由**：传统手机单摄后方完全是盲区，而后退踩空致伤风险极高。Insta360 的 360 度全景深度为后退保护提供了天然支持，是全景设备不可替代的降维打击功能。
- **独立测试验证**：使用者在静止状态下起步后退一步，API 在 200 毫秒内检测到运动状态变为后退（backward），输出的障碍物列表自动切换为身后最近的障碍物与身后地面落差。
- **验收场景**：
  1. **场景一（后退遇障）**：用户向后退步，后方 0.8 米处有一张矮凳。API 在用户后退初期立即输出该矮凳的相对坐标（Z > 0），标明为后方高危障碍。
  2. **场景二（后退防踩空）**：用户后方 1 米处为下行楼梯口，用户后退时，API 立即发出后方跌落紧急告警。

### 边缘情况 (Edge Cases)

- **相机穿戴倾斜与晃动**：用户行走时相机会产生俯仰与翻滚。底层 API 必须利用传感器数据进行重力方向对齐，确保输出的 $(x, y, z)$ 坐标系中，Y 轴严格平行且反向于重力方向（+Y 轴垂直向上表示高度），X-Z 水平地面严格垂直于重力方向，防止因相机倾斜将地面误判为障碍物。
- **运动状态瞬时误触发滤波**：在身体自然行走晃动或转身时，纵向加速度可能产生瞬时生理低频噪声（约 $\pm 0.1 \sim 0.2\text{ m/s}^2$）。API 必须采用双阈值判定（纵向加速度 $a_z < -0.3\text{ m/s}^2$ 且全景后半球深度变化率 $\frac{\Delta d_{rear}}{\Delta t} < -0.2\text{ m/s}$，持续 2 帧）并结合滑动滤波，防止将身体微晃或轻微转身误判为后退。
- **近距噪点与盲区（小于 0.3 米）**：当障碍物过于贴近镜头时，深度可能出现离群噪点或标记为盲区。API 需对此类数据进行安全兜底，统一将有效视野内的连续盲区转换为 0.3 米极近距离并赋予危险级别（`threatLevel = .danger`）输出，防止漏报。
- **平滑低纹理墙面与高反光镜面**：面对无纹理白墙或镜面时，深度估计可能出现瞬时跳变。API 统一采用平滑系数 $\alpha = 0.7$ 的指数滑动平均（EMA）滤波，在常数内存与零排序开销下剔除单帧孤立噪点且不增加显著时延。
- **相机通信闪断**：无线信号受到干扰导致丢帧或断连时，API 必须在 1 秒内对外输出连接状态异常事件，严禁内部静默挂起或输出脏数据。

## 需求规范 (Requirements)

### 功能需求 (Functional Requirements)

- **FR-001**：系统必须提供极简的原生设备控制 UI，包含“连接设备”与“断开设备”按钮，按钮触控尺寸至少为 48 乘 48 像素，并配置完整的 VoiceOver 无障碍标签与状态说明。
- **FR-002**：系统在成功连接 Insta360 全景相机后，必须在界面上实时渲染 1080P 全景视频流画面，支持视觉调试与实时画面监控。
- **FR-003**：系统必须在界面上提供传感器数据预览面板，显示当前相机连接状态、视频帧率（FPS）、三轴姿态角（俯仰/翻滚/偏航）与加速度数据；面板采用最基础的原生 Text 文本呈现，仅供视觉查看与被动读屏，严禁向 VoiceOver 发出任何实时主动语音通知与高频刷新干扰。
- **FR-004**：系统必须支持通过无线网络（Wi-Fi Socket，首期核心交付）连接 Insta360 全景相机（有线 USB 通道保留为后备方案），全面管理生命周期状态（未连接 noConnection、连接中 connecting、已连接 connected、连接失败 failed），并具备断线自动重连能力。
- **FR-005**：系统必须通过相机 SDK 持续拉取全景实时视频流，并实时解析六轴传感器（IMU）数据（三轴加速度与三轴角速度），保持图像帧与传感器数据的时间戳严格对齐。
- **FR-006**：系统必须能够从全景图像中估计全向物理距离，测距全量程覆盖 0.3 米至 5.0 米（全量程误差小于 5 厘米；其中 0.5 米至 3.0 米为核心避障精密区，平均误差小于 3 厘米）。
- **FR-007**：系统必须利用传感器姿态数据对空间点云进行重力对齐校准，消除相机倾斜对坐标系的影响。
- **FR-008**：系统必须通过对全景下半球深度点云进行实时纯动态平面拟合（如 RANSAC 平面解算，候选点到平面距离容差 $\epsilon \le 0.05\text{m}$），自适应动态计算相机当前离地高度与地平面方程，无需任何人工高度先验或静态标定，并据此剥离脚下平整地面，提取地面上方 0.1 米至 2.0 米之间的障碍物点云。
- **FR-009**：系统必须基于人体宽度（默认 0.6 米）计算前方安全通行走廊，输出建议行进方位角（度）、通道瓶颈物理净宽（米）以及安全可行进纵深（米），并给出走廊中心的三维空间导向锚点坐标 $(x, y, z)$（严格遵循 iOS 空间音频坐标系：前向纵深 $z \le 0$；导向锚点在走廊中轴线上的前向纵深统一取 $z = -\min(\text{passableDepth}, 2.0\text{ 米})$，确保空间音频始终处于最佳声学辨识与测距区间）。
- **FR-010**：系统必须利用相机 IMU 加速度计与全景前后深度差分，实时估计使用者的运动状态，划分为前行（forward）、静止（stationary）与后退（backward）。判定后退状态必须满足双阈值条件：纵向加速度 $a_z < -0.3\text{ m/s}^2$ 且全景后半球（180° 视野）平均深度变化率 $\frac{\Delta d_{rear}}{\Delta t} < -0.2\text{ m/s}$，且持续至少 2 帧（约 200ms），以有效滤除正常行走的步态晃动噪点。
- **FR-011**：在使用者处于前行或静止状态时，系统必须将主避障检测空间限定在人类生理视觉角度范围内（水平前向正负 60 度至 70 度，总视野约 120 度至 140 度），专注前向行进安全。
- **FR-012**：在使用者处于后退状态时，系统必须自动将避障与跌落检测空间动态切换为后向 180 度视野（倒车雷达模式），优先感知身后的障碍物与地面落差。
- **FR-013**：系统每帧输出的障碍物对象列表必须严格限制为最多 Top 3 个，采用综合威胁评分模型 $S = w_1 \cdot \frac{1}{\max(d, 0.3)} + w_2 \cdot \max(v_{approach}, 0)$ 进行动态排序与截断（其中 $d$ 为直线距离，$v_{approach} = -\frac{\Delta d}{\Delta t} = \frac{d_{t-1} - d_t}{\Delta t}$ 为相对接近速率，正值表示正在迎面逼近，负值表示远离；默认权重 $w_1 = 1.0, w_2 = 1.5$）。
- **FR-014**：每个输出的障碍物对象必须包含三维相对空间坐标 $(x, y, z)$（水平、高度、纵深，单位：米）、方位角（度）、垂直仰角（度）、绝对距离（米）、动态接近速率（米/秒）、综合威胁评分、威胁级别（`threatLevel`）以及是否为后方危险的标识（`isRearHazard`）。其中威胁级别遵循以下量化判定标准：
  - `danger`（危险）：处于有效视野盲区（$d < 0.3\text{m}$ 兜底），或绝对直线距离 $d < 1.0\text{m}$，或处于前向 1.5 米内且迎面逼近速度 $v_{approach} \ge 0.5\text{m/s}$；
  - `warning`（警告）：不满足危险条件，但绝对距离 $1.0\text{m} \le d \le 2.0\text{m}$，或 $v_{approach} > 0.2\text{m/s}$ 正处于接近态势；
  - `safe`（安全）：绝对距离 $d > 2.0\text{m}$ 且无明显逼近趋势（$v_{approach} \le 0.2\text{m/s}$）。
- **FR-015**：系统必须在前向（常态）或后向（后退状态下）0.5 米至 3.0 米监视范围内持续监测脚下地面高度变化，当出现超过 15 厘米的向下阶跃落差时，输出跌落隐患事件及其距离、方位与前后向属性（`isRearHazard`）。
- **FR-016**：系统必须以标准结构体或内存数据流形式对外暴露上述计算结果，接口三维坐标系必须与 iOS 空间音频（AVAudio3DMixing）保持直接兼容。
- **FR-017**：在相机连接断开或数据源异常时，系统必须在 1 秒内更新数据状态标志为异常，界面与屏幕朗读器同步发出警示。

### 关键数据实体 (Key Entities)

- **相机连接状态 (CameraConnectionState)**：
  - `noConnection`: 未连接；
  - `connecting`: 连接握手中；
  - `connected`: 已连接且正常推流；
  - `failed`: 连接失败。
- **传感器预览度量 (SensorTelemetry)**：
  - `connectionState`: 当前连接状态；
  - `fps`: 当前实时推流帧率；
  - `pitch`: 俯仰角（度）；
  - `roll`: 翻滚角（度）；
  - `yaw`: 偏航角（度）；
  - `acceleration`: 三维线性加速度 $(a_x, a_y, a_z)$（米/秒²）。
- **全景数据帧 (PanoramicFrame)**：包含全景图像像素缓存、采集时间戳、相机三轴加速度与角速度姿态。
- **物理深度矩阵 (DepthMatrix)**：全向 256 行乘 512 列的物理距离矩阵，记录每个方向的精确测距值（米）；通过带内特殊值（`Float.nan` 或 `<= 0.0`）表示无效点或超出量程，避免引入独立布尔矩阵以节省内存并加速向量化计算。
- **用户运动状态 (UserMotionState)**：
  - `forward`: 前行中；
  - `stationary`: 静止/停步观察；
  - `backward`: 正在后退或有后退起步倾向。
- **空间障碍物项 (SpatialObstacleItem)**：描述单个障碍物在使用者相对坐标系中的空间位置（每帧最多输出 3 项）：
  - `position`: 三维相对坐标 $(x, y, z)$，单位：米；
  - `distance`: 空间直线距离，单位：米；
  - `azimuth`: 水平偏转方位角，单位：度（负值为左，正值为右）；
  - `elevation`: 垂直仰角，单位：度（负值为低矮，正值为上方）；
  - `approachRate`: 动态相对接近速率（米/秒，$v_{approach} = \frac{d_{t-1} - d_t}{\Delta t}$，正值表示正在快速逼近）；
  - `priorityScore`: 综合威胁优先级评分；
  - `threatLevel`: 威胁级别（安全、警告、危险）；
  - `isRearHazard`: 是否为身后危险（布尔值，用于触发后方空间音频）。
- **通行走廊几何 (PassageCorridorGeometry)**：描述当前最佳通行走廊：
  - `isPassable`: 是否存在可通过走廊（布尔值）；
  - `recommendedSteeringAngle`: 建议行进方位角（度）；
  - `clearanceWidth`: 通道最窄处的物理净宽（米）；
  - `passableDepth`: 安全可行进纵深距离（米）；
  - `targetAnchor`: 通道中心的三维空间导向坐标 $(x, y, z)$（严格遵循 iOS 空间音频坐标系：前向 $z = -\min(\text{passableDepth}, 2.0\text{ 米}) \le 0$，供空间音频直接绑定引导音源；当 `isPassable == false` 时统一输出 $(0, 0, 0)$）。
- **跌落危险事件 (DropOffHazardEvent)**：描述地面踏空风险：
  - `distance`: 距离使用者的水平距离（米）；
  - `azimuth`: 危险边缘所在方位角（度）；
  - `dropDepth`: 预估向下落差深度（米）；
  - `isRearHazard`: 是否发生在身后（布尔值）。

## 成功指标 (Success Criteria)

### 可度量指标 (Measurable Outcomes)

- **SC-001（相机数据流与预览稳定性）**：Wi-Fi 连接成功率达到 98% 以上，开启推流后视频帧率稳定维持在 15 帧/秒以上，IMU 数据采样频率达到 50Hz 以上且与视频帧时间戳严格同步，画面预览无肉眼可见卡顿。
- **SC-002（控制与预览 UI 无障碍合规）**：连接与断开控制按钮的触控目标尺寸严格大于 48 乘 48 像素，配有 VoiceOver 无障碍标签；界面所有组件与文本对比度严格达到 4.5:1 以上；传感器数据面板刷新延迟小于 100 毫秒，且支持屏幕阅读器作为单一语义卡片整体聚焦朗读（遵循宪章边界阻断原则，以中文逗号平铺拼接）。
- **SC-003（端到端低延迟）**：底层全链路处理延迟（从图像输入到输出空间几何数据）控制在 130 毫秒以内，稳定维持每秒 8 帧以上的更新速率。
- **SC-004（物理测距高精度）**：在 0.5 米至 3.0 米的有效避障核心区间内，空间三维坐标与距离的平均测量误差小于 3 厘米（相对误差小于 3%）。
- **SC-005（通道几何识别率）**：在室内典型开门与过道测试中（如 0.9 米标准门宽），安全通行走廊的检出率达到 95% 以上，且建议方位角偏差小于 5 度。
- **SC-006（前向生理视角避障检出率）**：在前向生理视觉范围（120 度至 140 度）身周 2 米内，对体积大于 20 乘 20 乘 20 厘米的障碍物检出率达到 98% 以上。
- **SC-007（动态逼近加权有效性）**：当存在相对速度大于 0.5 米/秒的迎面逼近物体时，系统在 2 帧（约 250 毫秒）内将其动态提升为 Top 1 最高优先级。
- **SC-008（纯动态地平面自适应性）**：在相机高度在 0.8 米至 1.8 米（手持、胸前、头盔）变化时，地平面拟合误差小于 5 厘米，无需任何手动标定。
- **SC-009（跌落边缘预警时机）**：针对 15 厘米以上的下行阶梯或坑洼，在距离边缘 1.2 米前检出率达到 95% 以上。
- **SC-010（动态后退意图响应时效）**：从用户起步向后移动到系统切换为后向倒车雷达模式，检测响应延迟小于 200 毫秒（2 帧内），后向 2 米内障碍物与踩空危险检出率达到 95% 以上。
- **SC-011（空间音频接口直接可用性）**：上层空间音频引擎无需额外坐标变换，可直接利用本 API 输出的 `targetAnchor` 或 `position` 进行音源位置更新，数据对接耗时小于 1 毫秒。

## 假设与约束 (Assumptions)

- **硬件依赖与首要工作**：系统必须首先成功建立与 Insta360 全景相机的通信连接与流管道，全链路测试依赖真实硬件推流。
- **UI 极简与无障碍优先**：界面采用纯原生 SwiftUI 开发，严格遵守宪章的无障碍规范与最小触控目标规范，优先保证 VoiceOver 读屏友好与高对比度。
- **相机安装自适应**：全景相机支持手持、胸前、肩部或头盔佩戴，系统纯动态解算地平面与相机高度，要求镜头水平 360 度视野无遮挡，镜头正前方与身体朝向基本一致。
- **使用者移动工况**：假设用户处于正常步行速度（约每秒 0.8 至 1.2 米）。
- **下游使用方式**：假设上层业务层专门负责将本 API 输出的三维坐标赋予 iOS 空间音频节点，本模块自身不调用任何音频播放或震动驱动 API。
- **通信与计算资源**：假设在 iPhone 15 及以上搭载 Apple 神经引擎（ANE）的设备上独立脱机运行。
