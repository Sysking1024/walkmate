## 用户场景与独立测试

### 用户场景 1：Insta360 全景相机连接、控制 UI 与实时流预览（优先级：P1，已交付基线）

作为开发者和系统使用者，我希望在手机上能有一个极简的原生控制界面，可以一键连接或断开 Insta360 全景相机，全面管理相机的生命周期；并在连接成功后，能够直接在界面上看到全景实时视频预览画面，以及实时的六轴传感器（IMU）姿态数据面板，以便直观验证相机通信正常、画面流畅、姿态数据同步，为下游空间感知算法提供坚实的数据源保障。

- **优先级理由**：没有真实相机的实时画面与传感器数据输入，下游的模型推理与空间避障均无法运转。
- **独立测试验证**：在 iPhone 上点击“连接设备”，应用与 Insta360 相机在 2 秒内完成握手建连，界面实时渲染全景视频流（每秒 15 帧以上），传感器面板持续刷新三轴姿态角与加速度；点击“断开设备”后，安全释放流并断开连接。
- **验收场景**：
  1. **场景一（设备连接与实时画面渲染）**：打开 App，点击“连接设备”按钮（尺寸至少 48x48 像素，配有 VoiceOver 标签），应用成功连上相机 Wi-Fi，界面中央立即流畅播放全景实时预览画面，无黑屏与画面撕裂。
  2. **场景二（传感器实时数据面板）**：界面下方的信息面板实时显示当前连接状态（如“已连接”）、实时帧率（FPS）、三轴姿态角（俯仰/翻滚/偏航）与加速度数值，数据随相机转动连续平滑刷新；遵循无障碍边界阻断原则合并为单一语义卡片，支持 VoiceOver 整体聚焦并以中文逗号平铺朗读。
  3. **场景三（主动断开连接）**：点击“断开设备”按钮，系统安全关闭流播放器并断开连接，预览画面清空，状态更新为“未连接”。

### 用户场景 2：全场景 360° 障碍物数据与目标跨帧跟踪（优先级：P1，核心威胁感知）

作为上层调用方，我希望底层 API 能够每帧向我推送空间中所有被检出障碍物的统一结构化数据。全景 360° 视野内的各类危险源（包括**地面障碍物、高空悬挂碰头物、地面跌落/下行断层台阶、以及动态移动实体**）全部统合在同一障碍物模型中输出。每个障碍物都具备在连续时间内的**稳定跟踪 ID（Tracking ID）**、三维相对坐标、极坐标方位、物理包围盒尺寸、动态相对接近速率以及危害分类，以便调用方能够统一获取全场景危险分布。

- **优先级理由**：360° 全向统一输出消除了死角，将高空悬挂、低矮凸起与下行跌落统一为标准障碍物对象，避免调用方维护多套分散接口。
- **独立测试验证**：在测试环境中设置不同类型的危险源（地面箱子、离地 1.6 米悬挂标牌、向下 20 厘米台阶断层），API 在同一障碍物列表中统一输出这三者，均具备准确的三维坐标、分类与稳定的 Tracking ID。
- **验收场景**：
  1. **场景一（地面障碍与连续跟踪）**：当使用者朝向前方 2 米处地面箱子移动时，API 输出该障碍物数据并分配持久 `id`（分类为 `groundObstacle`），随着距离缩短，`id` 保持不变，相对接近速度准确反映逼近态势。
  2. **场景二（高空悬挂碰头物检出）**：正前方 1.5 米处存在离地 1.6 米的悬空树枝或广告牌，API 输出该物体坐标（垂直高度 $y > 0$），分类明确标注为 `hangingHazard`。
  3. **场景三（地面跌落与下行阶梯检出）**：脚下前方 1.2 米处出现超过 15 厘米的向下阶梯或深坑断崖，API 输出该危险项，分类标注为 `dropOffHazard`，并计算出向下落差深度与危险边缘方位。
  4. **场景四（动态行人相对速度监测）**：迎面有行人走来时，API 将其归类为 `dynamicEntity`，并正确计算出相对接近速率（如 $v_{approach} > 0.6\text{ m/s}$），威胁级别提升为 `danger`。
  5. **场景五（身侧与身后全向覆盖）**：使用者向侧方移动，障碍物滑移至身侧及后方，在全景 360° 范围内其数据持续稳定输出，不因离开正前方而丢失。

### 用户场景 3：连续可通行路线与路径折线点解算（优先级：P1，核心通行导航）

作为上层调用方，我希望底层 API 能够基于当前鸟瞰空间（BEV）解算出前方一条连续的安全可行走走廊，并向我输出一组**按行进次序排列的路径折线路标点（Waypoints）**、每个折线点处的物理净宽（瓶颈宽度）以及最大安全纵深，以便调用方能直接获取通向开阔区域的最佳路径几何。

- **优先级理由**：行进导航的核心在于“找到安全通路”。输出连续的折线路标点序列能够准确描述真实环境中的弯道、开门走廊以及拐角。
- **独立测试验证**：在设有障碍物的走廊或开门场景中，API 规划出避开障碍物、通往开门处的一组平滑折线点（间距约 0.3 至 0.6 米），并在每个点标注通道物理净宽。
- **验收场景**：
  1. **场景一（直线畅通走廊）**：前方开阔无阻，API 输出沿前向延伸的折线点序列，净宽大于 1.5 米，安全纵深达标。
  2. **场景二（障碍阻挡下的绕行路径）**：前方正中受阻，侧方存在可通过通道，API 输出绕过阻挡物的折线点序列，首个推荐偏角指向通道中心。
  3. **场景三（完全受阻）**：前方完全封闭（无满足人体宽度的安全通道），API 输出通路状态为不可用，折线点列表为空，安全纵深为 0。

### 用户场景 4：空间音频与空间几何转换工具箱（优先级：P1，核心数据转换工具）

作为上层调用方，我希望底层 API 提供一套**无状态的纯计算工具箱（SpatialAudioKit）**，能输入三维相对坐标，纯数学计算输出符合 iOS 空间音频标准的 `AVAudio3DPoint` 坐标与衰减参数、符合普通耳机的双声道平衡值（Pan）、以及适合语音播报的钟表方位描述（如“11 点钟方向 1.8 米，低矮障碍”）。工具箱必须是纯数据计算，不涉及任何底层音频播放。

- **优先级理由**：将复杂的坐标旋转、声学参数换算与钟表方位编码沉淀为标准纯函数，确保调用方零额外计算开销，同时避免与系统音频会话产生冲突。
- **独立测试验证**：调用工具函数传入三维测试坐标，微秒级返回符合规范的音频锚点、双声道声相与钟表方位文字，过程中无任何硬件驱动调用。
- **验收场景**：
  1. **场景一（钟表方位逆空间编码）**：输入方位角 -30°、距离 1.8 米、垂直仰角 -15°，工具函数返回结构化数据：钟点为 11、文本描述为“11点钟方向，前方 1.8 米，低矮障碍”。
  2. **场景二（原生 3D 空间音频参数）**：输入物体相对坐标 $(0.5, 0.0, -2.0)$，工具函数返回对应的空间音频声源锚点 `(x: 0.5, y: 0.0, z: -2.0)`、推荐衰减音量以及声源扩展角。
  3. **场景三（双声道立体声参数）**：输入偏角 45°、距离 1.0 米的障碍物，工具函数返回声道平衡值 `pan = 0.707`（偏右耳）、推荐脉冲间隔与音调调节参数。
  4. **场景四（几何净空检测）**：传入目标偏角、身体宽度与当前帧障碍物列表，工具函数在 50 微秒内返回该方向指定距离内是否存在碰撞冲突、最近冲突距离以及冲突障碍物 ID。

### 边缘情况 (Edge Cases)

- **相机穿戴倾斜与行走晃动**：利用传感器姿态进行重力方向对齐，确保输出的 $(x, y, z)$ 坐标系中，Y 轴严格平行且反向于重力方向（+Y 轴垂直向上表示高度），X-Z 水平地面严格垂直于重力方向，防止因相机倾斜将地面误判为障碍物。
- **目标短暂遮挡与跟踪维持（Occlusion & Re-identification）**：当物体被短暂遮挡时，内部维持 5 帧（约 500ms）的状态预测缓存，若物体重新出现则继承原 Tracking ID，防止 ID 频繁跳变。
- **临界宽度通道通行判定（0.55m ~ 0.65m）**：当通道间隙接近人体宽度（0.6 米）时，引入滞后区间（Hysteresis），开通门槛为 0.65 米，关闭门槛为 0.55 米，防止路线折线点频繁震荡。
- **超近距离盲区（< 0.3 米）**：当障碍物过于贴近镜头时，统一将有效视野内的连续盲区转换为 0.3 米极近距离，赋予 `danger` 威胁级别输出，防止漏报。
- **平滑低纹理墙面与高反光镜面**：采用指数滑动平均（EMA）滤波，在常数内存与零排序开销下剔除单帧孤立噪点且不增加显著时延。
- **相机通信闪断**：无线信号异常中断时，API 必须在 1 秒内对外输出连接状态异常事件，严禁内部静默挂起或输出陈旧脏数据。

## 需求规范 (Requirements)

### 功能需求 (Functional Requirements)

#### 1. 硬件连接与数据基石（已交付验证，保持基线）
- **FR-001**：系统必须提供原生设备控制 UI，包含“连接设备”与“断开设备”按钮，按钮触控尺寸至少为 48 乘 48 像素，并配置完整的 VoiceOver 无障碍标签。
- **FR-002**：系统在成功连接 Insta360 全景相机后，必须在界面上实时渲染全景视频流画面，支持视觉调试与实时画面监控。
- **FR-003**：系统必须在界面上提供传感器数据预览面板，显示当前相机连接状态、推流帧率（FPS）、三轴姿态角（俯仰/翻滚/偏航）与加速度数据；面板采用原生文本呈现，支持 VoiceOver 作为单一语义卡片整体聚焦朗读。
- **FR-004**：系统必须支持通过无线网络（Wi-Fi Socket）连接 Insta360 全景相机，全面管理生命周期状态（`noConnection`、`connecting`、`connected`、`failed`），并具备断线自动重连能力。
- **FR-005**：系统必须通过相机 SDK 持续拉取全景实时视频流，并实时解析六轴传感器（IMU）数据，保持图像帧与姿态数据的时间戳严格对齐。

#### 2. 全景深度与空间几何基础
- **FR-006**：系统必须基于 DAP 模型从全景图像中估计全向物理距离，测距全量程覆盖 0.3 米至 5.0 米（全量程误差小于 5 厘米；0.5 米至 3.0 米核心避障区平均误差小于 3 厘米）。
- **FR-007**：系统必须利用传感器姿态数据对空间点云进行重力对齐校准，消除相机倾斜对坐标系的影响，保证 Y 轴与重力严格平行反向。
- **FR-008**：系统必须通过对全景下半球深度点云进行纯动态平面拟合，自适应动态解算相机当前离地高度与地平面方程，无需人工高度先验或静态标定，并据此剥离平整地面，提取有效障碍物点云。

#### 3. 全场景 360° 障碍物数据 API (All-Scene Obstacle Data)
- **FR-009**：系统必须提供全场景 360° 障碍物数据输出接口，每帧在统一的障碍物列表中输出检出的所有危险物体，单个障碍物对象必须包含：
  - 跨帧唯一跟踪标识符 `id`（在目标连续移动期间保持稳定）；
  - 三维相对空间坐标 `position`（$(x, y, z)$，单位：米，严格遵循 iOS 空间音频右手坐标系：+X 为右, -X 为左, +Y 为上, -Z 为前向纵深, +Z 为后方）；
  - 直线距离 `distance`（米）、方位偏角 `azimuth`（度，-180° ~ +180°）、垂直仰角 `elevation`（度）；
  - 物理空间三维包围盒尺寸 `size`（宽、高、深，单位：米）；
  - 障碍物分类 `category`：
    - `groundObstacle`：地面凸起障碍物（箱子、椅子、立柱等）；
    - `hangingHazard`：高空悬挂或碰头危险（离地 > 1.4 米的悬空树枝、招牌等）；
    - `dropOffHazard`：地面下沉断层（落差 > 15 厘米的下行楼梯、深坑台阶等）；
    - `dynamicEntity`：动态移动行人或物体；
  - 相对运动速度矢量 `relativeVelocity`（$(v_x, v_y, v_z)$，单位：米/秒）与标量相对接近速率 `approachRate`；
  - 综合威胁优先级评分 `priorityScore`、威胁等级 `threatLevel`（`danger`、`warning`、`safe`）以及身后危险标志 `isRearHazard`。
- **FR-010**：系统输出的障碍物列表为全景 360° 全量检出的有效障碍物数组，每个物体包含完整的空间几何与威胁指标，底层不做任何人为的 Top N 截断，由上层调用方按需进行业务筛选或排序。

#### 4. 可通行路线折线数据 API (Passable Route Polyline)
- **FR-011**：系统必须基于鸟瞰（BEV）自由空间栅格与人体宽度约束（默认 0.6 米），提取并输出连续的可通行路线数据，包含：
  - 通路可用状态标志 `isPathAvailable`；
  - 连续路径路标点序列 `waypoints`（按行进次序排列，每个路标点包含三维空间坐标 `position` 以及该位置处的物理净宽 `clearanceWidth`）；
  - 最大安全可行进纵深 `safeDepth`（米）；
  - 起步推荐行进偏角 `recommendedHeading`（度）。
- **FR-012**：规划算法必须优先选择与使用者当前朝向夹角最小且物理净宽最开阔的平滑通道，路标点间距控制在 0.3 米至 0.6 米之间。

#### 5. 空间音频与空间几何转换工具箱 (SpatialAudioKit)
- **FR-013**：系统必须提供纯计算工具库 `SpatialAudioKit`，其所有方法均为无状态纯函数，**不包含任何音频播放逻辑与音频硬件会话配置**。
- **FR-014**：工具箱必须提供钟表方位逆空间编码方法 `toClockDirection(azimuth:distance:elevation:)`，将相对角度与距离换算为标准的钟点点位（1 至 12 点钟）、文字描述（如“11点钟方向，前方 1.8 米”）以及高矮层次文案（“低矮地面”、“平齐视线”、“悬空碰头”）。
- **FR-015**：工具箱必须提供原生 3D 空间音频参数换算方法 `toSpatialAudioRenderParams(position:boundingSize:)`，将相对三维坐标转换为 iOS 空间音频所需的 `AVAudio3DPoint` 坐标、距离衰减系数（0.0 ~ 1.0）以及声源扩展角。
- **FR-016**：工具箱必须提供双声道立体声参数换算方法 `toStereoFallbackParams(azimuth:distance:)`，计算左右耳平衡度 `pan`（-1.0 纯左至 +1.0 纯右）、基于距离的脉冲蜂鸣间隔时间（毫秒）以及音调调节系数。
- **FR-017**：工具箱必须提供快速几何净空校验方法 `checkClearance(heading:userWidth:depth:against:)`，允许调用方传入当前帧障碍物列表（`[ObstacleItem]`），主动探测指定宽度沿指定偏角行进指定距离内是否存在包围盒碰撞冲突，并在 50 微秒内返回最小冲突距离与最近障碍物信息。

#### 6. 数据通用规范
- **FR-018**：系统输出的所有数据模型必须遵循 Swift 原生强类型协议并支持 `Codable`，既支持内存直接传递，也支持序列化为标准 JSON 字符串。

### 关键数据实体 (Key Entities)

- **全场景障碍物集合 (ObstacleData)**：单帧输出的障碍物聚合体，包含帧编号、时间戳及 `ObstacleItem` 数组。
- **单个障碍物项 (ObstacleItem)**：包含持久追踪 ID、三维相对坐标、极坐标、长宽高包围盒、分类（地面/悬挂/跌落/动态）、相对速度与威胁等级。
- **障碍物分类 (ObstacleCategory)**：枚举类型，包含 `groundObstacle`、`hangingHazard`、`dropOffHazard`、`dynamicEntity`。
- **可通行路线数据 (PassableRouteData)**：包含通路可用性、起步推荐角度、最大安全纵深及路标点数组。
- **路径路标点 (RouteWaypoint)**：沿路线顺序分布的三维航路点及其所在位置的物理通行净宽。
- **空间音频渲染参数 (SpatialAudioRenderParams)**：工具箱输出的原生 3D 声源锚点坐标、音量衰减与声源扩展角。
- **立体声降级参数 (StereoFallbackParams)**：工具箱输出的左右声道平衡 Pan、蜂鸣脉冲周期与音调调节乘数。
- **钟表方位文案数据 (ClockPromptData)**：工具箱输出的 1~12 点钟方位数字、米数距离、层次修饰词及组装好的中文语音朗读文案。

## 成功指标 (Success Criteria)

### 可度量指标 (Measurable Outcomes)

- **SC-001（相机数据流与预览稳定性）**：Wi-Fi 连接成功率达到 98% 以上，开启推流后视频帧率稳定维持在 15 帧/秒以上，IMU 数据采样频率达到 50Hz 以上且与视频帧时间戳严格同步，画面预览无肉眼可见卡顿。（已达成基线）
- **SC-002（控制与预览 UI 无障碍合规）**：连接与断开控制按钮的触控目标尺寸严格大于 48 乘 48 像素，配有 VoiceOver 无障碍标签；传感器数据面板刷新延迟小于 100 毫秒，且支持屏幕阅读器作为单一语义卡片整体聚焦朗读。（已达成基线）
- **SC-003（端到端处理时效）**：底层全链路处理延迟（从图像帧输入到输出障碍物与路线数据）控制在 130 毫秒以内，稳定维持每秒 8 帧以上的更新速率。
- **SC-004（目标跨帧追踪稳定性）**：在连续移动过程中，对 3 米内持续可见的障碍物，跨帧持久跟踪 ID 保持率达到 90% 以上，无频繁 ID 闪烁或跳变。
- **SC-005（全向测距与多类型障碍物精度）**：在 0.5 米至 3.0 米的核心避障区间内，空间三维坐标与直线距离测量平均误差小于 3 厘米（相对误差小于 3%）；针对地面凸起、离地 > 1.4 米的高空悬挂物、以及 > 15 厘米的向下阶跃跌落断层，综合检出率均达到 95% 以上。
- **SC-006（路线折线点连续性与净宽精度）**：在典型门框或走廊场景中，提取出的路径折线点首尾平滑，路标点净宽计算误差小于 5 厘米，走廊检出率达到 95% 以上。
- **SC-007（空间音频工具纯计算零损耗）**：`SpatialAudioKit` 的各项单次数学转换执行耗时严格小于 0.05 毫秒（50 微秒），且 100% 不触碰系统音频会话。
- **SC-008（钟表逆空间编码准确率）**：方位角到 1~12 点钟方位的换算准确率达 100%，正前方 ±15° 严格映射为 12 点钟。
- **SC-009（标准数据序列化能力）**：所有输出数据模型在满足 Swift 原生强类型零拷贝访问的同时，支持标准 JSON 序列化输出，序列化耗时小于 2 毫秒。

## 假设与约束 (Assumptions)

- **硬件与算力平台**：系统基于 iPhone 15 及以上搭载 Apple 神经引擎（ANE）的设备脱机运行，输入源为真实的 Insta360 全景相机。
- **相机安装与视野**：全景相机支持手持、胸前或肩部佩戴，镜头水平 360 度视野无遮挡，镜头正前方与身体朝向基本一致。
- **纯粹数据与转换接口**：底层 API 专注于物理空间感知解算与声学几何参数换算，不包含任何具体的发声逻辑与业务玩法规则。
